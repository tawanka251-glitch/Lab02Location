# AR ตามพิกัด (Location-based WebAR) · 0214381 Lab 3

เว็บ AR แสดงผลวัตถุ 3 มิติ ตามพิกัดสถานที่จริง (Location-based WebAR) บนโทรศัพท์มือถือ สำหรับใบงาน Lab 3 พัฒนาด้วย **A-Frame 1.6.0** และ **AR.js 3.4.8**

---

## 1. สรุปสิ่งที่ระบบนี้ทำ (System Overview)

- **เป้าหมายของระบบ:** เป็นเว็บ AR ตามพิกัดสถานที่จริง (Location-based WebAR) สำหรับใบงาน Lab 3
- **เทคโนโลยีที่ใช้:** A-Frame 1.6.0 (จัดการฉาก 3 มิติ) + AR.js 3.4.8 (จัดการกล้องและพิกัด GPS)
- **การทำงาน:**
  - ดึงภาพสดจากกล้องหลังของโทรศัพท์มือถือมาเป็นฉากพื้นหลัง
  - อ่านพิกัด GPS และเข็มทิศของโทรศัพท์
  - นำภาพจำลอง 3 ภาพ (Minecraft, Stardew Valley, Don't Starve) ไปวางไว้ ณ พิกัดจริงในระยะ **ไม่เกิน 5 เมตร** รอบตัวผู้ใช้
  - เมื่อผู้ใช้เดินถือมือถือส่องไปรอบ ๆ จะเห็นภาพทั้ง 3 ลอยอยู่ในโลกจริง และแถบสีม่วงด้านบน (HUD) จะบอกพิกัด ความแม่นยำ และระยะห่างของแต่ละจุดแบบเรียลไทม์

## 2. การวิเคราะห์ปัญหา (ทำไมในคอมติด แต่มือถือจอดำ)

| สาเหตุ | รายละเอียดทางเทคนิค |
| --- | --- |
| **1. บั๊ก videoTexture กับ GPU มือถือ (ตัวการหลัก)** | ในคอมพิวเตอร์ การ์ดจอและ WebGL สมบูรณ์ ทำให้ AR.js ดึงภาพกล้องไปแปะลงใน Three.js Texture ได้ทันที แต่บน Android / Samsung ชิปประมวลผลกราฟิก (GPU) มักไม่ยอมวาด Texture แบบเรียลไทม์หากมีข้อจำกัดเรื่องเฟรมเรตหรือขนาดวิดีโอ ผลลัพธ์คือ Three.js วาดฉากพื้นหลังเป็นสีดำสนิท ทับภาพกล้องจริง |
| **2. เลเยอร์ Canvas 3D ทับวิดีโอ** | ใน A-Frame 1.6.0 ตัว Canvas 3D จะถูกตั้งค่าเริ่มต้นให้มีพื้นหลังทึบแสง หากคำสั่งเคลียร์ฉาก (ClearColor) ไม่ได้ถูกสั่งให้โปร่งใสแบบ Alpha = 0 แผ่น Canvas สีดำจะบังตัววิดีโอด้านหลังจนมิด |
| **3. กล้องติดสถานะ Hardware Lock** | ในมือถือ ระบบอนุญาตให้แอปเรียกใช้กล้องได้ทีละ 1 สตรีมเท่านั้น หากมีโค้ดพยายามเรียก `getUserMedia` ซ้ำซ้อนขณะที่ AR.js กำลังเชื่อมต่อกล้อง ตัวระบบ Android จะบล็อกสัญญาณกล้องทันที ทำให้ไม่มีภาพส่งมา |

## 3. แนวทางแก้ไขให้ใช้งานได้ (เปิดกล้องแล้วติด ไม่จอดำ)

### 🛠️ ส่วนที่ 1: แก้ไขในโค้ด (`index.html`)

1. **แก้ปัญหา Canvas ทึบแสง:**
   - ใส่คอมโพเนนต์ `transparent-canvas` สั่ง Three.js เคลียร์ฉากเป็นแบบโปร่งใส 100% (`renderer.setClearColor(0x000000, 0)`) ทำให้มองทะลุ Canvas 3D ไปเห็นภาพกล้องจริงด้านหลังได้อย่างสมบูรณ์
2. **ไม่แย่งการจับกล้อง:**
   - ลบสคริปต์ภายนอกที่แย่งขอสิทธิ์กล้องออกทั้งหมด เพื่อไม่ให้เกิด Hardware Lock ให้ AR.js เป็นตัวเรียกเปิดกล้องตัวเดียวอย่างเป็นเอกเทศ
3. **จัดเลเยอร์วิดีโอแบบ Native Video Layer:**
   - ตัด `videoTexture: true` ออกจาก `arjs`
   - บังคับให้แท็ก `<video>` ของกล้องแสดงผลเต็มหน้าจอที่เลเยอร์หลังสุด (`z-index: -1`) ซึ่งเป็นวิธีที่เสถียรที่สุดบนมือถือ Android ไม่ต้องพึ่งพา Texture ของ GPU ที่มักมีบั๊กจอดำ

### 📱 ส่วนที่ 2: สิ่งที่ต้องตรวจสอบที่เครื่องโทรศัพท์มือถือ

1. **ตรวจสอบสิทธิ์กล้องระดับเครื่อง Android:**
   - ไปที่ **การตั้งค่ามือถือ (Settings) → แอป (Apps) → Chrome → สิทธิ์ (Permissions) → กล้อง (Camera)** → ต้องเลือกเป็น **"อนุญาตขณะใช้แอป"**
2. **ปิดแอปที่อาจแย่งใช้กล้อง:**
   - ปิดแอปกล้องถ่ายรูป, แอป LINE หรือแอปอื่น ๆ ที่อาจเปิดค้างอยู่ในพื้นหลัง
3. **เปิดผ่าน Chrome โดยตรง:**
   - เปิดผ่าน **Google Chrome** บนมือถือเท่านั้น (ไม่เปิดผ่านเบราว์เซอร์ของแอป LINE หรือ Facebook)
